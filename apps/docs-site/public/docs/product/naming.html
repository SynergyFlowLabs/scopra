Scopra Product and Component Names

Status: Proposed naming map
Scope: Architecture and product-facing component names

Scopra remains the umbrella product. Its components use a shared, Mercury-exploration-inspired naming system. These names identify parts of Scopra; they are not separate products.

NameComponentResponsibility
ScopraProductControlled execution infrastructure for AI agents.
Scopra MarinerCLI, onboarding, and enrollmentGuided CLI/TUI onboarding and machine enrollment.
Scopra MioLocal daemonRegisters workspaces, maintains the authenticated machine connection, and coordinates local execution.
Scopra CalorisCloud control planeIdentity, grants, cloud policy, sessions, approvals, and control-plane APIs.
Scopra GoldstoneRelaySecure agent-to-machine message relay.
Scopra Messenger ProtocolInternal protocolVersioned, authenticated request and dispatch envelopes between cloud services and the local daemon. This is distinct from the Model Context Protocol (MCP).
Scopra ResolutionPolicy engineEvaluates cloud and local policy decisions.
Scopra RupesLocal enforcement boundaryApplies local maximum policy and enforces the final authorization decision on the machine.
Scopra HollowExecution sandboxEphemeral, rootless, isolated environment for approved work.
Scopra CatenaAudit chainAppend-only chain of attributable execution and security events.
Scopra FaculaSecurity signalsSecurity signals and anomaly detection.

Naming and implementation notes

  • Use the full name at first mention in product-facing documentation; the short component name (for example, Mio or Catena) is fine afterward.
  • Resolution evaluates policy; Rupes is the local enforcement boundary. Cloud authorization may narrow local authority but must never broaden it.
  • Goldstone is the relay service; Messenger is the protocol carried through the system. Messenger does not refer to MCP.
  • The current executable names remain scopra for the CLI and scoprad for the daemon. Mariner and Mio are the component names; changing executable names, package paths, service identifiers, or wire-level identifiers requires a separate compatibility decision.
  • Confirm trademark, domain, package-registry, and repository-name availability before public launch.
