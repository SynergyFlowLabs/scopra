System Overview

AI agent / MCP host
  -> MCP or HTTPS entry point
  -> Scopra Caloris (identity, grants, cloud policy, sessions, approvals)
  -> Scopra Goldstone (secure agent-to-machine relay)
       carries Scopra Messenger Protocol envelopes
  -> Scopra Mio (local daemon)
       -> Scopra Resolution (policy evaluation)
       -> Scopra Rupes (final local authorization and enforcement boundary)
       -> Scopra Hollow (rootless isolated execution environment; ADR-010)
       -> Scopra Catena (append-only audit and execution-event chain)

Scopra Resolution evaluates applicable cloud and local policy. Scopra Rupes applies the local maximum and is the final authorization and policy-enforcement authority; Scopra Hollow supplies execution containment. Cloud services may narrow but cannot broaden local authority. Approved operations run inside Scopra Hollow. Scopra Facula represents the security-signal and anomaly-detection layer; Scopra Mariner provides local CLI/TUI onboarding and machine enrollment.

The first local-control increment runs scoprad (Mio) in the foreground and lets scopra status (Mariner) query a read-only status endpoint over a bounded Unix socket. Mio keeps its socket and lock in a persistent per-user state directory ($XDG_STATE_HOME/scopra by default), and an exclusive lock ensures that at most one Mio serves a state directory. scopra doctor reuses that endpoint for read-only platform, state-directory, workspace-registry, and daemon checks, revalidates registered workspaces read-only (ADR-004), and can check the host's ADR-010 containment setup and the configured image with two read-only Podman queries; it never starts Mio or changes local state. At startup Mio opens its workspace registry (ADR-005) in the locked state directory and refuses to serve if the registry is unusable. It then serves workspace registration (add, list, remove) on the same socket (ADR-006), which scopra workspace uses; workspaces are validated under ADR-004. The same socket also serves local execution (execution.run, ADR-011): Mio revalidates the registered workspace, runs the command in Scopra Hollow (ADR-010) when containment is configured, and streams the start notice, output, and result back. Without --sandbox-image or Podman, every run is refused with containment_unavailable. scopra run is the Mariner side of that path: it resolves --workspace or --path, sends the run, writes output to stdout and stderr (or as JSON lines with --json), and returns the command's exit status. For durability, scopra service install writes a systemd user unit whose ExecStart carries the daemon path, the state directory, and the pinned image, then enables and starts it (ADR-012); uninstall reverses that, and status reads only systemd's answers. Mio also keeps a bounded, metadata-only journal of answered runs, <state-dir>/runs.jsonl (ADR-013): one line per run with its execution and workspace IDs, state, times, exit code, and stdout/stderr byte counts, and never the command line, arguments, path, or output. execution.logs serves it read-only on the same socket, and scopra logs prints it as text or schema-v1 JSON. It is a local debug record, not Catena: it is not tamper-evident, the user can delete it, and a journal that cannot be opened stops Mio while a failed append stops later runs. Policy decisions, approvals, and audit are not exposed by this endpoint. See ADR-003.
